## Relaciones Principales

### USER (1) ←→ (*) BOOKING
- Un usuario (cliente) puede tener múltiples reservas
- Un usuario (profesional) puede atender múltiples reservas

### SERVICE (1) ←→ (*) BOOKING
- Un servicio puede tener múltiples reservas
- Una reserva pertenece a un servicio

### USER (PROFESSIONAL) (1) ←→ (*) AVAILABILITY_RULE
- Un profesional puede tener múltiples reglas de disponibilidad
- Una regla pertenece a un profesional

### USER (PROFESSIONAL) (1) ←→ (*) TIME_OFF
- Un profesional puede tener múltiples períodos de ausencia
- Un período de ausencia pertenece a un profesional

### SERVICE (*) ←→ (*) USER (PROFESSIONAL)
- Relación muchos a muchos a través de tabla intermedia
- Un servicio puede ser ofrecido por múltiples profesionales
- Un profesional puede ofrecer múltiples servicios

### BOOKING (1) ←→ (*) NOTIFICATION_LOG
- Una reserva puede tener múltiples notificaciones
- Una notificación puede estar asociada a una reserva

## Índices

### USER
- email (unique)
- role + is_active

### BOOKING
- (client_id, status)
- (professional_id, status)
- start_datetime
- (status, start_datetime)

### AVAILABILITY_RULE
- (professional_id, day_of_week, start_time) (unique)

### NOTIFICATION_LOG
- (recipient_id, status)
- booking_id
- created_at

## Restricciones

### BOOKING
- start_datetime < end_datetime
- client.role = CLIENT
- professional.role = PROFESSIONAL
- No overlapping bookings para mismo profesional

### AVAILABILITY_RULE
- start_time < end_time
- professional.role = PROFESSIONAL
- No overlapping rules para mismo profesional/día

### TIME_OFF
- start_date <= end_date
- professional.role = PROFESSIONAL

## Estados de Transición (BOOKING)

```
    PENDING
    │
    ├─→ CONFIRMED (profesional acepta)
    │   │
    │   ├─→ DONE (tras la cita)
    │   └─→ CANCELED (cliente/profesional cancela)
    │
    └─→ REJECTED (profesional rechaza)
```
